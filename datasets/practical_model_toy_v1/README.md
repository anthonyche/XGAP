# Same-request model / strong / execution development fixture

Five nodes, nine directed edges. Eight KNOWS edges preserve the prior tiny facts;
one FOLLOWS edge links Alice to Zoe. Both predicate candidates are genuine frozen
schema/data entries and compile to different, independently authored answers.

The trusted intake only supplies the fixed bounded skeleton. Person identity,
age >= 30, source and target type are explicit request bindings. The Chinese
phrase “熟人” remains an unresolved predicate; the model proposes KNOWS or FOLLOWS.
Only that predicate may remain unvalidated in the development PERFORMANCE mode.
Wrong predictions keep their actual wrong answer; no semantic/answer repair.

All four model outcomes (two candidates, unavailable, error) must have feasible
continuations. The binding-only clarification fixture is separate from gold and
read only when invoked. Its closed two-answer contract assumes the authored file
is available; unexpected I/O failures terminate visibly. It is additional trusted
information for that branch, not an equal-information accuracy comparison.

The frozen profile tries the model before experiment clarification, using explicit
search priority and zero post-feasibility improvements. Neither action has a known
latency estimate. This is a declared first-feasible ordering, not proof that the
model is faster than local clarification or the globally cheapest policy.

`snapshot/` was published offline with `xgap.catalog.build`; runtime only verifies
and reads it. `gold.json` is accessed for scoring only after the result is stored.
This is one bounded template/slot E2E gate, not open-domain NL or a paper result.
