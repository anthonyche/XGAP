Financial syntax profile v3 adds the complete local response specification below.
It is generated by the same code used for local admission, not a query template.
The service still enforces only the envelope; use this full specification to
construct all nested parameters correctly. Output a candidate envelope, not a
JSON Schema, explanation or example. Never rewrite the question to fit an example.

Two different condition languages have different field names. A row Filter uses
{op:"and",args:[...]} or {op:"or",args:[...]}, and {op:"not",arg:...}.
Path conditions use kind/conditions. Do not combine op with conditions.

Every property-read map has output alias on the left, stored property on the
right. For example, properties:{"business_key":"id"} reads stored id into the
business_key column. properties:{"id":"business_key"} instead reads a stored
property literally named business_key. Use only stored properties in the schema.

Entity holes are identity predicates. If the schema declares identity_property
xgap_id, the legal node descriptor is properties:{"xgap_id":{"$hole":"h"}}
where h is the entity hole. Do not attach that hole to a name property. If another
dataset uses a different identity_property, use that declared property instead.
Entity_field is a separate output column containing canonical identity. Preserve
canonical and business columns until joins and final projection are complete.

Project is DISTINCT over its projected columns. Preserve an edge key when later
aggregation must count parallel edges separately, even if their amounts are equal.
The entire local contract follows; its field names override informal conventions.
