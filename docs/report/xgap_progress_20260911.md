## 当前语义边界

XGAP 第一版支持固定集合中的只读、有限、类型明确的查询，不追求通用查询语言。
Match、Traverse、Filter、Project、Join、Union、Aggregate、OrderLimit、Align 的
具体条件、排除项与逐层证据已写入 [查询契约](../bounded_query_profile_v1.md)。
LLM 负责把自然语言转为语义表示并提出待绑定项；catalog 帮助解析实体、模式和来源。
算子规定能表达什么，compiler/runtime 负责保持其答案含义。三层不能互相替代。

例如通用关联 NOT EXISTS、关系 LEFT OUTER JOIN、UNION ALL、窗口、自定义函数、
无限递归在第一版范围外；范围内的错误不能以“暂不支持”掩盖。路径 Optional 不是
关系外连接。开发可固定较小的实际展开长度 L，但代码并未新增全局3-hop限制。
有限路径不决定图直径，LIMIT 也不保证中间结果或内存有界。

## 目前的结果具体长什么样

最新T2-B把受控NL模板真正接到了同一个问题入口：**5/5程序、18/18候选答案、
10/10独立目标正确**，原双库slice保留。独立解析意义与旧gold逐项一致；可执行
硬约束进入计划，provider不能预先确认entity候选或修改调用方硬约束。77项focused
通过，完整回归**3,394通过/38跳过**，24个harness/example入口通过。响应与失败可以保存后离线回放；这仍是受控解析，
真实模型质量尚未测得，通用backend回放也未声称完成。

最新 T2-A 原生结果：**5/5 agent 程序、18/18 候选答案、10/10 独立目标正确**，
永久双库 slice 正确。当前87项 focused 与517项日常测试通过；完整回归 **3,362通过/38跳过**，24个
harness/example入口通过。
这证明小型固定版本目录能接入真实查询链，准备文件移除后仍能运行；没有进行大
GrailQA 重建，也没有把受控语义模板计为真实 LLM 理解结果。

此前布尔条件步骤已提交 `400f0cf`：20 个路径问题在两后端共40/40执行、40/40
独立目标正确；4 个 Match 程序共8/8执行、8/8独立目标正确。

已验收类型语义：**15/15 程序、32/32 合法候选、27/27 独立目标查询正确**。
这组数字来自保留的分项验收记录；前期参考查询差异和补测范围完整保留，未把失败
算成成功。当前实际生成的15个选中计划与已执行计划完全相同，原始 toy/gold 未改。

可以直接演示的结果包括：

- `9007199254740993 + 2` 精确返回整数 `9007199254740995`。
- 高精度 decimal 求和返回 `10000000000000000000000.25`，不经过 float。
- 对 `1、1.0、true、"1"、null`，总行数为5，非空数为4，不同非空值为3。
- 按该字段跨库连接得到6对实体；`1` 与 `1.0` 匹配，Boolean 与 null 按独立规则处理。
- 在一个来源选择 Alice，与另一个来源的 decimal 属性连接后，得到精确聚合结果。
- 永久保留的 Neo4j 路径＋Fuseki 属性过滤＋coordinator join 仍返回 Alice→Cara。

该类型步骤日常 gate 为489项通过、26.35秒，加18题原始演示；最终完整回归为
**3,334项通过、38项跳过，24个 harness/example 入口全部通过**。
这些结果证明受测语义可以跨编译、规划和执行保持正确，**还不能证明真实 NL 准确率、
大数据性能提升或 SOTA 优势**。不把不同测试组相加当作独立 benchmark 样本。

既有正式研究证据仍保留其边界：FinBench-derived 的32个 held-out 查询上，计入
当次选择成本的时间比为0.3096，物理赢家选择30/32；但 fixed-A 和 family-global
选择相同，尚不支持实例 memory 的额外收益，冷家族 fallback 0/16的负结果也保留。
这部分引用既有准入记录，本轮未重算。详见
[系统与实验评估](xgap_system_experiment_assessment_20260910.md)。

## 离完整系统还差什么

目前 **T0 已完成；T1 已形成有限查询契约及原生能力证据；T2-A/T2-B 已验收，T2 整体与 T3 尚未验收**。
按已确定的系统目标，还需通过以下三道验收门：

1. **确定性核心完整性。** 按已冻结的查询 profile 和 operator-by-layer 支持表，修复新发现的范围内错误，
   检查逻辑、参考、编译和运行时一致性。当前有限 profile 不等于任意程序支持；
   无界递归、可变长路径中的数字位置条件等仍有边界。更一般的源划分、流式/批处理、
   取消与代价校准也需要明确实现和测量。
2. **可复用的 agentic 闭环。** 独立验收 Interpretation 与 deterministic planning；
   catalog 的 offline build→freeze/version→runtime-only lookup 必须在所有入口成立，
   并保存可以离线复现的最小失败。新通用入口的冻结目录链已具备真实执行证据，legacy 迁移与通用回放尚未验收。
3. **真实集成与评价。** 真模型接入同一查询入口，轻量 UI 展示实际计划/结果/失败；
   先做冻结的 GrailQA-mini 真实集成，再跑完整 GrailQA、FinBench 与相应 baseline/消融。
   当前 UI 主要围绕既有实验会话，新通用入口还需贯通。

当前主要瓶颈是这些系统边界与支持范围尚未全部闭合。GPU 影响真实模型质量测试，
不阻塞确定性核心、catalog 生命周期、回放和 UI 接口工程。大 catalog 重建不再是
开发前置条件；完整 GrailQA 不承担日常 debug。

XGAP 无须覆盖全部查询语言。语义范围外的查询不构成永远未完成的开发义务；
范围内的编译、执行和约束错误仍必须修复。Interpretation 理解错误与 operator
支持边界分开报告，见 [有限语义范围](../decisions/bounded_system_scope_v1.md)。

不报告缺乏验收分母的完成百分比，也不承诺尚无测量依据的全部达标日期。
下一轮立即将真实模型接入同一toy问题入口，完成小数据开发门后推进冻结真实样本比较；保持每一步都有独立答案、
模块测试和同一完整 vertical slice。功能完成与研究假设成立分别验收。
