- **起点预筛选**（076c2f4、0f62658）：在原有属性读取上筛选候选起点，以去重后的身份键连接三个路径分支的第一条边，保留原最终过滤。只有能够证明安全的使用路径才应用；不把control专有属性放入graph，不增加源请求。物理输入不修改共享baseline查询、语言、提示或估计器权重。
- **小图结果**：5实体/8边的独立预期6行全一致。原有连接输出78→36；计入新增起点连接后全部连接输出为48。源调用两侧都是8次。并行边、重复provider键、属性冲突、空起点、限制/OR/独立根以及循环依赖边界均检查。首版5项通过0.91+0.26秒；物理形式调整后5项定向复验0.87秒，未做广泛回归。

## 算法和当前结论

预筛选是一次确定性等价变换，不通过实际试跑寻找起点或最优计划。设n为语义算子数、p为谓词数、e为DAG边数、L为物理计划大小，保守构造时间/空间上界均为O(p·n·(n+e)+L)，最多新增n+2个运行节点；现有策略域仍至多1+2J。估计器只在有界域内按预测选优，没有实际物理最优或近似比保证。内存/时间执行复杂度不等同于规划复杂度。

结果支持“缺少早期约束会制造可避免的中间结果”这一工程判断。它没有证明SF0.1内存问题已经完全解决；当前仍读取原始源响应，冻结估计器也没有校准这类新计划的实际选择性收益。后续必须记录真实新请求的表现，不把小图78→48行数解释为时延提速。
