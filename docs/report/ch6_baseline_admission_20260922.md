## 实际结果

不是 FinBench SF0.1 正式评价，也没有重复测量平均值。

|ARUQULA→Fuseki，单源组件|116.42 s|46|4 行内部账户 ID|4 行业务 ID|0 / 0|
|ARUQULA→FedX，单源|44.11 s|26|4 行内部账户 ID|4 行业务 ID|0 / 0|

耗时为方法进程启动到完成，包括前端、模型、工具查询、原作者后处理及最终数据库请求；
不含离线装载、lookup 索引构建、输入凭据和结束后的独立评分。worker 内部对应
115.70、43.37、62.89 s。不同配置和随机轨迹不能用于宣称两链路提速比。

两个 FedX 用例采用相同 https-iris-action-schema-fedx-v2 配置、代码提交 269a5b3。
单源有 10 次端点查询、10 次源请求、5 次 lookup，输入/输出 tokens 为 34,888/3,021。
跨源有 13 次端点查询、100 次源请求、15 次 lookup，输入/输出 tokens 为 71,451/4,852；
源请求分布为 graph 63、control 37，全部 HTTP 成功。次数包含原作者探索过程，
不是每题只调用一次模型或数据库。两者均完成一次最终提交；全部自建服务已关闭。

单源将内部 account_31 等标识当成业务 ID，参考要求字符串 1–4。跨源最终查询使用了
冻结源中不存在的 owner/from/to/status 谓词，合法执行后返回空表。没有注入正确谓词、
改答案或做额外答案修复。这些方法输出按原样进入评价。

不能再声称该串接“只能运行单源”：它已在两源部署完成调用和最终执行。
也不能把这两题外推为 baseline 普遍无效，或据此宣称 XGAP 胜过 SOTA。

## 必要适配

- 保留 ARUQULA 作者提交 9a3982baca03d62f7250572e300b1e4ba47727cc，原 checkout 不变。
  使用原控制器、探索动作、提示词、最终查询选择和后处理。
- 使用共享 Qwen qwen3.8-27b，关闭 thinking 模板；不是原论文模型成绩的复现。
- 已有三个动作字符串字段使用严格 JSON schema。最终 FedX 配置只将格式化步骤
  的上限从 700 调为 2048 tokens，避免重新序列化时产生半截查询。控制器的 700-token
  上限、采样值和搜索逻辑未扩大；没有字段别名修补或新增重试。
- 两个工具补齐 HTTPS 绝对 IRI 编码；FedX 配置对一个固定实体标签工具模板作等价改写，
  避开空 COALESCE 和 NULL 绑定接口故障。不改最终模型查询。
- FedX 5.1.2 外部类逐字节保持一致。无效的 OPTIONAL 配置开关试验保留为失败，
  最终配置恢复原默认路径。未替 FedX 去重或调整优化器策略。

这是披露适配的 ARUQULA→FedX 外部组合，不能标成全字节未改的作者系统；
适配前后不同配置的失败不能混合为同一次正式实验成绩。

## 验证与证据

9 个相关 worker 边界测试通过。原客户端离线 wire 检查确认提示词/采样参数保留，
结构化输出配置到达实际请求体。模板变换在同一 Jena fixture 上 4/4 原始/适配结果一致。
