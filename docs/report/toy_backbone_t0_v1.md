## Compiler/data-encoding gap reproduced locally

M9 Cypher/SPARQL compilation is available for 7/18 cases; the explicit directed
compiler is available for 8/18, adding IN. Availability is not result correctness.
Running the actual directed SPARQL artifacts over the ordinary-triple fixture
produces the following binding counts:

| Query | Expected identity-preserving paths | Actual compiled RDF bindings |
|---|---:|---:|
| T02, all edges | 8 | 7 |
| T03, Alice's one-step paths | 3 | 2 |
| T05, Alice's two-step paths | 6 | 4 |
| T15, reverse paths from Bob | 2 | 1 |
| T16, two-step paths with different endpoints | 5 | 3 |

The emitted edge binding is `https://xgap.test/toy/KNOWS`, the predicate IRI,
not a unique edge identity. The ordinary triple collapses e1/e7. The fixture's
independent targets explicitly use edge resources and preserve both identities.
This does not mean a simple RDF graph is corrupt: the representation cannot
encode the property-graph path-identity contract. A caller must not infer that
plain-RDF compilation is a faithful multigraph path implementation.

The first T1 repair should make edge representation/capability explicit and
support identity-preserving RDF compilation for the existing reified fixture,
while preserving legacy plain-RDF semantics. Do not add a new path-algebra
operator, silently fabricate duplicate paths from expected answers, or change
the frozen toy graph to remove the failure. IN semantic/logical representation,
Union/recursive compilation and remaining selector support remain separate
listed gaps; fixing the edge representation will not close all of T1.
