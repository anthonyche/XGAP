# FinBench同事实映射：小图和真实Fuseki验证

新离线适配器已实现：读取已核验的FinBench分区，生成具有共同身份的原生装载文件、
结构RDF、控制属性RDF和编译映射。原分区不变；不构建runtime catalog，不读取答案
或测量数据。原生边保留原sourceKey，平行转账不会压成一条RDF关系。

本轮仅使用8个实体、16条关系的合成小图。它覆盖跨类型同名ID、平行转账、严格递增
时间、相等/倒序时间、环路、两个符合条件的medium和时间窗边界，不是FinBench SF0.1。

## 已验证的结果

三项新局部检查覆盖身份/事实保持、三类查询的独立答案，以及新mapping进入普通
Match编译器后与原生身份规范化一致。首次2通过、1失败；失败是测试把既有tuple
返回约定写成list，修正测试后只补跑这一项，通过。没有修改core来迎合测试。

真实Fuseki5.6.0运行三条查询，每条一次，全部与手工推导答案一致：

| 查询语义 | 实际答案 | 说明 |
|---|---|---|
| 直接转账、封禁账户、金额聚合 | 公司1：账户2=66.000；账户3=9.000 | 保留平行转账；包含窗口右端点 |
| ≤3跳递增时间、无环、封禁medium | 4行：账户2距离1对应medium1/2；账户3距离1/2对应medium1 | 相同时间、倒序和回到起点路径不混入 |
| 风险medium、公司金额排名 | 公司1=56.000 | 排除窗口右端点；多个medium不使金额重复累计 |
