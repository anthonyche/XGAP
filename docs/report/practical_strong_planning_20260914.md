# Practical strong planning：首个可执行里程碑

2026-09-14。用户批准[当前方案](../practical_planning_20260914.md)后恢复工程。
基线为 bbc8873；本轮只改新协调器、显式普通入口路由、定向测试和配套文档。
没有启动模型服务、远程作业、大图实验、catalog build、训练或 baseline 修改。

## 已实现

- 有限深 AND/OR strong-policy 搜索：保留每个动作的全部声明结果，全部分支可完成
  才选该动作；先保留可行方案，再在限额内尝试改进。
- 有界全局状态/动作/深度与逐路径资源预算；可行性、停止原因、估计分数分开报告。
- 完整物理计划的先行构造。缺估计器、可选优化域超限时依然保留合法基础计划。
- EXACT 的结构/槽位验证；PERFORMANCE 的具名预测授权。度量尚未定义，明确
  输出 metric_deferred，不接受伪 epsilon 保证，禁用旧的无相应误差界的关系截断。
- 通过 GoalLoop 实际读取一次澄清结果并执行一次最终计划；验证其来源/版本/目标
  槽位，未建模结果或最终数据库失败终止，不重试或切换另一个语义分支。
- 普通 `run_question` 的可选新路由；原模板 Interpretation 接入同一协调器，解释
  调用计入剩余资源预算。旧 strict/one-shot 路由不变。

主门20项新风险检查通过（0.94秒），另2项已知后端可用性补充检查通过（0.37秒），共22项新检查。普通入口改动另检查3个现有 one-shot 用例，均通过。
测试期间执行实际编译的 SPARQL，后端由 RDFLib 7.1.4 的进程内测试客户端承接；
这是 typed binding/compiler/runtime 集成证据，不是新的真实 Fuseki/Neo4j 服务测量。

## 首轮失败与修复

首次17项检查中15过、2失败。两个失败暴露了真实实现问题：

1. 编译器的计划 ID 可能由不同实体绑定共用。原策略终点索引以该 ID 为键，Alice
   分支被 Bob 终点覆盖。现用完整查询、物理计划和证据的内容标识区分策略终点；
   Alice/Bob 两条分支各有独立答案测试，未改 gold。
2. 动作生成发生在规划 deadline 检查之前。现先检查预算，再请求下一个动作，
   已有可行方案继续保留。

修复后17/17通过。普通入口和最终失败边界新增2项：最初失败检查误把“一个最终
联邦计划”当成“只能有一次源调用”；实际是两个不同源片段而非重试。修正检查为
1最终计划、源调用无重复、实际计数一致，随后通过。再加入未知用量案例，最终20/20。
只针对当前新风险和受影响入口检查，没有运行完整回归套件。

## 结论与尚未实现

已经证明新的策略能连接实际语义绑定、编译与执行，且不是仅定义了 dataclass。
对有条件计划，所有声明结果可行与实际只走一条分支同时成立。已知可行计划不会
仅因为估计器或优化域问题丢失。20项测试通过时间不是 planner 延迟或论文提速数据。

没有证明总体速度提高、强计划在任意输入上必定可得、真实 NL 准确率提升或全局最优。
完整强策略只针对声明的有限结果模型；真实未建模网络/服务失败仍可能发生。

下一门是 catalog/能力/可选 LLM 动作的统一适配和新路由的真实小图服务验证。
普通开放 NL 的结构权威验证、用户将定义的 discrepancy、逐跳绑定传播、正式模式
发布和新策略的完整论文评价均未完成。旧 FinBench44个方法结果和全部失败仍保留，
本轮没有继续 group11，也没有追溯给旧结果贴新算法标签。

补充审计：已知缺少某后端适配器时，在规划前排除该副本；另一副本可用则仍实际返回
正确答案，所有副本不可用则不报告strong。2项新增边界检查通过，避免选完计划才
因为已知缺失的适配器失败。新增BindingAction结果唯一性检查另以3个受影响分支
案例验证（0.53秒）。
