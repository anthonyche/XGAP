# SF0.1 自然语言端到端首版验收 — 2026-09-16

本轮已完成首版真实 NL 观测，但还没有达到可主张整体性能或准确性优势的论文评价。
EXACT 全程无人值守；无需用户逐题澄清、操作或验证。12 个独立自然语言问题对应
72 个方法观测单元，全部封存并自动评分；本轮 53 个托管服务会话全部关闭。

## 实验究竟执行了什么

输入只有 NL 及通用冻结 schema/catalog。每单元真实调用一次 qwen3.8-27b，K=1，
最多 4096 输出 token，不修复或重试。模型提出紧凑逻辑查询，确定性 lowering 生成
semantic DAG 和逻辑源映射，当前 strong planner 选择一个最终执行方案。没有当前题
候选计划试跑、按实测挑赢家、重新拟合估计器或人工补 gold。

- 数据：FinBench v0.1.0 SF0.1 的冻结投影，55,604 节点、309,577 条关系。
- 问题：此前 48 题自建 workload 按冻结顺序每家族取前 4 题，合计 12 题；选择不读
  参考答案或方法结果。它们不是官方原版题目，也不是未暴露测试集。
- Native：Neo4j + Fuseki 异构部署，12 题 × 2 个 XGAP 模式 = 24 个单元。
- RDF：相同事实转成 RDF 的联邦部署，12 题 × 4 个方法 = 48 个单元。外部方法是
  共同 NL 前端 + 作者 FedX/FedUP；两种部署不是两个独立数据集。
- 每单元一次观测，不是 72 道题或六轮取平均。catalog、数据、索引、估计器与作者引擎
  artifact 均复用既有冻结版本；一次性构建不重复计入在线费用。

执行后评分才读取参考答案。比较遵循冻结的类型、数值、重复行和顺序契约。执行失败
即使遇到空参考也不能算正确。全体分母、失败类别和预算截断全部保留。

### 失败与截断

|范围|观测|解释边界|
|---|---|---|
|四组 XGAP 各自|4/12 时序多跳题触发 2 GiB 方法 RSS 上限|执行已开始，不能归类为不会出 plan|
|Native 两模式各自|1/12 模型变量命名不合法，未发出最终查询|解释/接口失败，保留原模型输出|
|RDF Performance|1/12 触发累计 12 GiB artifact 存储上限|整批环境预算截断；不是该题答案错误或 EXACT 更精确的证据|
|共同前端 + FedX|12/12 在响应量预算下未完成|不是正确执行时间，不可用作 XGAP 提速分母|
|共同前端 + FedUP|11 次作者引擎 HTTP 500；1 次模型传输失败|保持原生响应和未知 token，不优化或修复 baseline 结果|

已检查的 FedUP 原生 500 响应以 `extend` 代数节点开始；这里只报告实际错误，
不据此声称其所有查询能力或整体算法不如 XGAP。FedX/FedUP 本轮没有共同成功范围，
因此没有可报告的 SOTA 效率优势。一次模型传输失败也不算作者引擎失败。

### 成本

全部 72 个方法单元各有 1 次已知模型调用，合计 **72 次**。已知 token 合计
**252,955**；其中一次传输失败未返回 token usage，此合计不等于完整精确账单。
被内存/磁盘 guard 中止的 XGAP 原回执不改写；其已完成模型响应的 usage 通过
封存后校验 SHA 的只读汇总恢复。没有完整 core receipt 的规划/执行分阶段时间保持未知。

|XGAP 组|已报告规划 CPU 中位数|样本数|
|---|---:|---:|
|Native EXACT|78.368 ms|7|
|Native Performance|33.086 ms|7|
|RDF EXACT|44.504 ms|8|
|RDF Performance|13.894 ms|7|

当前规划 CPU 是几十毫秒，正确题在线总时间是十几至几十秒。减少这部分 search 的
时间尚未明显改变整个链路；这不否定未来减少昂贵信息动作的意义。本版共同 K=1 前端
没有可供评价的交互 acquisition 分支，不能证明 clarification/token Pareto 机制。
在线时间包含模型、目录读取/grounding、规划、最终执行与共同记录边界；数据库启动、
离线构建与评分分开。远端 LLM GPU 时间未测得。

## EXACT 的无人值守契约

EXACT 不能依靠用户逐题回答或验证。当前 NL profile 没有人类澄清工具或逐题权威
fixture；声明 hole 必须通过可用的自动权威证据门。证据不足则自动返回未解决/失败，
不会暂停整个实验等待用户，也不会把模型置信度或 gold 冒充权威。

这里的 strong 保证**以模型生成的查询结构为条件**。即使没有 hole，模型给出的
结构和字面值也未必符合用户原意；类型检查、成功编译和 EXACT 均不能证明 NL 已被
正确理解。可信模板入口的严格默认契约未放松，模型结构的 opt-in 标记不是 BindingEvidence。
被 guard 中止且没有完整 core 回执的单元，只依据持久化 dispatch 和源调用证明最终执行
已开始，不额外补写 strong 成功证明。

## 这批结果给出的工程优先级

1. **优先减少多跳中间结果。** 已检查的一道内存失败题把 1–3 hop 展开为 36-operator
   DAG，多分支读取/连接转账关系后才接入起点过滤；单个 native 方法在终止前已有
   14 次源调用和 145,544,039 响应 bytes。候选方向是起点绑定传播、必要过滤前移、
   受控遍历和等价读取共享。先在小图重现并保护方向、时间条件、重复边和聚合语义；
   这是依据结构与资源观测提出的诊断，还不是已经测得的优化收益。
2. **改进评价覆盖及实验预算隔离。** 冻结非空/选择率分层，明确历史曝光；将累计日志
   存储触发与方法级内存/响应预算分开呈现，避免队列位置导致的截断被解读成方法能力。
   保留本版数据，不删除或覆盖失败，也不按输出挑“好看”的题。
3. **解释失败用小图与保存的响应重放处理。** 检查变量标识与结构接口；不用这 12 题
   反复调 prompt、自动修答案或更新 estimator。
4. **模式研究后续再对准信息动作。** 当前两模式执行相同源工作、共同前端支付相同
   模型调用，继续扩大消融没有明确价值。先使有界执行稳定，再讨论下一版自动 acquisition、
   K>1 与 d/risk；不预设 Performance 必胜，不 claim 全局最优。

以上为下一轮候选，本轮收尾后进入结果讨论，没有启动扩量、调参或重跑。
