## 1. 当前情况与可支持的结论

基于 [9月16日首版报告](report/nl_strong_first_pass_20260916.md)、封存审计、当前
`compact_lowering.py` 的路径构造及既有 FedShop 静态材料进行分析，未重新运行方法。

|方面|已有证据|当前缺口及责任|
|---|---|---|
|真实端到端|12 个 NL 问题、72 个方法观测完成封存评分；有真实模型、规划与双后端答案|有界链路已通；不能据此称任意 NL 或全部声明实验已验证|
|执行稳定性|四组 XGAP 各有 4 道多跳题方法内存超限；其最终执行已开始|工程与物理规划负责降低中间结果，不能将其全部写成“不会出 plan”|
|题目覆盖|12 题中 11 题空参考；唯一非空题的 10 行在四组 XGAP 中都正确|采样/参数分布与覆盖不足；空答案题本身仍是必要负例|
|模式机制|两部署共同正确题上的源调用与 bytes 相同；配对时间比约 1.02 / 1.00|用户推进理论和 d/risk；随后接入可观察的信息动作差异，不先以大批调参强迫 Performance 获胜|
|外部对照|FedX 预算截断；FedUP 原生 500 或模型传输失败；另有隔离的接线失败|有可用候选方法；当前输入、适配与预算下尚无有效共同成功范围，不说明找不到 SOTA|
|计量环境|RDF Performance 的一个单元被累计 artifact 容量截断|累计存储与方法预算需要隔离，防止队列位置影响被误读为精度差别|

EXACT 继续无人值守，但必须有一个可查询、持有权威意图的模拟用户。现实用户不在逐题
交互循环中；需要clearance时向模拟用户询问并继续，不因现实用户未答而失败。
模拟用户可私有持有gold语义/意图标注，通过有范围、有记录的回答提供权威信息。
撤回先前禁止此类oracle的解释。未获确认的结构仍不能因类型检查而被视为正确意图。
细节见[模拟用户设计修正](decisions/simulated_user_authority_v1.md)，现已接入第一版，后续信息选择仍需机会分析。

### 多跳瓶颈：已经看到什么，尚未证明什么

当前 lowering 为每个长度构造一条连接分支，再合并 1–3 hop 分支；时间和一般条件
在相应连接之后施加。一个已检查的 native 失败单元含 36 个 operators、14 次源调用、
约 145.5 MB 响应。这个构造与中间结果膨胀相符，但尚未将峰值内存逐项归因。
已有 anchor/progressive 策略不等于这批 NL 生成 DAG 已获得有效起点传播。

下一步检验的假设是：将可证明安全的起点限制、单边时间过滤和必要条件尽早传播，
并减少等价重复读取，可以在保持答案语义的前提下降低工作量。不能用增加 hop 上限、
简单加内存、删条件、丢路径或无限扩展 planner 搜索替代这个验证。

缺口包括：多命名空间 IRI、必需/可选属性、字面值词法/类型/语言标签、bag 与重复事实、

## 2. 研究问题与评价轨道

固定查询轨与 NL 轨分别成图、分别记分母。Native Neo4j+Fuseki 和 RDF 是不同部署；
同事实转换不增加独立数据集数量。内部变体仍只能服务机制验证，不能代替外部方法。

|轨道 / Research question|X-factor|Y-factor|控制与比较边界|
|执行：有界规划是否能控制联邦工作量？|方法；分别变化 hop、扇出、起点选择率|正确完成率、在线时间、峰值 RSS、中间行数、源调用/bytes、planner CPU|先同语义小图；正式外部比较使用相同 RDF 查询、事实和资源|
|效果：NL 到答案链的可靠性如何？|方法、查询家族、空/非空及选择率分层|答案 EM、按结果语义定义的 precision/recall/F1、解释/计划/执行失败分解|初始输入只有 NL 和通用 schema；可按协议询问模拟用户；执行后独立评分|
|扩展：随数据与联邦增长如何退化？|数据量、源数、query/DAG 大小分别变化|正确完成率、median/p95、通信量、RSS、规划 CPU|单因素变化；不把源数变化同时造成的数据量增长解释成纯源数效应|
|模式：自动信息获取与执行成本如何权衡？|用户确定的 discrepancy/risk 参数、歧义分布、真实信息成本|质量、总在线成本、模型/token、证据/源调用、certificate CPU|待用户理论接入；强/弱集中、便宜 acquisition、退化 EXACT 等负收益条件均应保留|

“更快”必须指明相同任务下相对哪个方法。失败保留总分母；正确题配对时间只作补充，
另报截止前正确完成比例，不能拿失败终止时间计算 speedup。未知值保留，重复运行
或同模板改写不视为新的独立题目。不存在凭样本数自动成立的显著性承诺。

## 3. 恢复后的阶段与验收门

### M0：接入可查询的权威模拟用户

负责：工程。该能力是用户澄清后的明确要求，不等待新d/risk理论。复用已有权威证据
与信息动作边界，向当前NL入口接入模拟用户，私有状态由gold语义/意图自动准备。
支持实体/关系/时间等澄清及声明范围内的结构确认；每次只按问询范围答复。
解释器/planner获得的是已发生的交互回复，不提前读取隐藏意图、完整答案或最优物理计划。

先用少量小图覆盖：单槽、多槽、错误候选、结构确认、证据作用域和模拟用户状态完整性。
在权威信息完备、语义支持且预算允许的例子中，必须无需现实用户参与而完成
NL → 询问模拟用户 → 权威回复 → 更新意图/策略 → 最终执行 → 独立评分。
询问次数、实际处理时间和另行声明的模拟用户成本分别记录；不能用人工延迟制造优势。
拟加入的交互流程是 `NL + simulated-user interaction`，旧72单元保持`NL-only`证据身份。

### M1：在小图修复执行风险，并隔离环境截断

负责：工程。允许改动范围待恢复后按根因收窄到 XGAP lowering、物理策略、执行或
共同计量；不改 baseline 算法、数据答案、模式理论或历史发布。

1. 将保存的失败结构降到极小独立图，固定 NL → gold semantic query → logical plan
   → target query → expected result；分别走 Interpretation 与 deterministic planning。
2. 用起点高选择性、少量大扇出、1/2/3 hop、环、重复边、严格时间递增、重复变量、
   空结果和非空聚合覆盖新风险。优先最多 12–16 个有区别的小例，不铺全套回归。
3. 先定位哪一步放大行数，再采用最小的等价限制传播/过滤前移或读取共享。
   所有重写保护方向、时间边界、路径模式、重复行、聚合贡献和硬约束。
4. 复用可行 seed；候选构造和 lowering 展开必须给出关于 operators、sources、hop 界限的
   多项式时间/空间上界。预算界不是质量近似比，少中间结果也不自动等于更低实际延迟。
5. 将方法级 RSS/通信上限与整批可用存储分开计量；启动前检查容量，环境无法容纳时
   记为未运行/环境截断，不能归为方法无计划或答案错误。不通过删除旧 artifact 腾出结果空间。

**验收：** 全部新增语义例与独立参考一致；目标扇出例中观测到更少无关中间行/读取，
且完整小图 vertical slice 能执行。仅在修改触及真实外部边界时跑一次对应 live tiny 门。
若只有 planner CPU 下降或偶然时间变快，不据此进入大批实验。保持 one-final-plan、
无人值守、无当前题候选试跑；效果改善可同时惠及两个模式。

### M2：建立作者原查询上的有效外部对照

负责：工程与实验。先检查作者路线，再做 XGAP 的受限输入映射；不实现通用 SPARQL 引擎。

1. 复用已固定作者源码和静态审计，恢复后只检查缺少的运行依赖。冻结环境/数据配置，
   在最小作者语义用例上核对 FedX/FedUP、参考答案和真实调用。必要环境/传输修正属于
   适配；任何作者算法、查询优化规则、能力补齐、答案修复或按输赢调参均禁止。
2. 保留 12 个作者模板、原始 SELECT/DISTINCT、FILTER 和排序。逐模板记录
   已支持、待验证、不支持的具体原因；不能仅凭关键词或“编译成功”判支持。
3. q09 验证 IRI 和完整源覆盖；q12/q01 检查能否在现有有界语义内得到非平凡连接对照。
   包括两源含相同谓词、重复事实、跨源贡献的反例。不能只选择一个分片作为完整答案，
   不能向 XGAP 提供 gold RSA；不能添加 DISTINCT 掩盖 bag 语义差异。
4. 优先复用作者原查询，并验证到 XGAP IR 的语义等价映射。固定查询的引擎比较不调用
   LLM，明确标成 execution track；它不计入 NL 端到端结果。

**规模命名：** 官方 quick start 的 miniature 为 20/40 endpoints、12 模板共 24 次实例化。
已有批准的 2/4/8 源路线是 **FedShop-derived**。先用派生的两源小例做接入，第一次有界
比较也可沿此范围；数据/模板常数/参考须重新独立冻结，不从完整查询中删除来源。
若采用官方 miniature，需先满足机器容量；不能承诺它与派生小规模具有相同成本或结果。
[作者教程](https://github.com/GDD-Nantes/FedShop/wiki/1.-Quick-start)

**验收：** 小型基准有至少一个确实含多源贡献的非平凡连接模板形成共同正确完成记录，
并有全 12 模板的 coverage 分母；随后才冻结正式方法比较子集。这只是可比性门，不证明
广泛 SOTA 优势。若仍只有简单单三元组可比，或需要大范围新增语义，报告缺口并停止扩展，
交由用户决定是否扩大系统边界。baseline 的原生失败照实保存，不重跑到成功。

### M3：冻结更有信息量的 FinBench NL 评价集

负责：实验设计与数据管线。采样规则先于模型/方法输出，独立答案不进入推理。
gold语义可以用于准备模拟用户的私有权威状态，交互回复是声明的信息获取路径。

- 建议首个新批次 **24 个问题**，三家族各 8 个；每家族目标 6 个非空、2 个有效空结果。
  这是有意分层的诊断评价，不声称自然问题分布或完全未见模板；所有抽样/排除规则披露。
- 非空题还需覆盖选择率、分支规模和聚合贡献，不能都是低成本答案。固定有界候选池，
  根据独立参考确定分层；若某家族达不到预定格数，报告缺口，不能无界生成或看方法成绩换题。
- 旧 12 题及历史 48 题作为已暴露证据保留。修复重放属于 development，不并入新批次，
  新参数也不能冒称全新模板；prompt/estimator 只在开发划分调整。
- 维护每题 NL、gold semantic query、预期逻辑与目标查询、参考结果；NL 与形式语义的
  一致性按构造和规则检查；生成模拟用户的权威状态与可回答范围，不让现实用户逐题做
  validation，也不以 LLM judge 替代结果评分。

**验收：** manifest 的空/非空与家族格数、词义/类型/时间/重复行规则、曝光标签和评分
边界明确；支持与不支持项均可追溯。M1 小图门通过后才发出新评价请求。
24 是首批工作量建议，不是统计功效或论文覆盖充足性的保证。

### M4：分别封存固定查询比较和 NL 端到端首批改进结果

前置：固定查询轨需要 M1 的相关稳定性门与 M2 共同支持门；交互NL轨需要 M0、M1 与 M3，
若加入外部引擎还需 M2 的共同支持。固定查询轨不等 NL manifest 或模式理论；NL 主轨
仍必须真实调用模型并记录整个入口成本。

- 固定查询：XGAP-RDF、FedUP、FedX，在相同 RDF 源和查询事实下同图比较。
  初次可行性观测每单元一次；形成共同支持后，正式计时建议预定 3 个平衡 block，
  不因输赢添加轮次；以题为统计单位，报告共同成功范围和全部失败。
- NL 端到端：FinBench native 两模式；RDF 在已验证的共同语义范围加入明确命名的
  “共享 NL 前端 + FedUP/FedX”。每方法支付自己的模型和信息费用，不能把组合包装成
  作者系统原生支持 NL。交互比较给予各方法相同模拟用户接口/权限；外部组合的交互规则
  预先固定并披露，作者引擎不改。新协议中任务数、方法数、重复数逐项相乘，避免“48/288题”混淆。
- KBQA-R1 保留为后续原生 KBQA 条件下的外部轨；作者模型/权重、完整事实范围与工具
  权限要对齐。当前 Qwen endpoint 可用不代表其作者模型已经部署，不以临时换模型称复现。

首先交付五类图表：全分母正确完成、截止前正确率、失败分解、在线时间与可观测分阶段成本、
源调用/传输。有有效数据后才安排规模图；保留整体 16–20 图目标，消融最后做，不为凑图运行。
离线 catalog/summary/训练单列并按 Q 摊销；重复会话维护另记，未知 observer 开销不直接扣除。

**验收：** 每项结论有同权限外部对照或明确“不适用”；无法形成共同正确执行时不发布速度比。
不存在改引擎、删困难题、补答案、评价训练或隐藏重试。版本与结果封存后才进入下一批。

### T：用户理论与模式机制支线

用户推进 d/risk、discrepancy-bounded early execution 和 AND/OR policy 的数学契约。
工程阶段不自造误差保证，不把性能模式定义成必须处处更快，也不通过故意放慢 EXACT
制造差异。理论就绪后先核对：自动可获得的证据、允许的近似、终止条件、certificate 费用、
退化 EXACT 的边界、PTime 构造与解质量声明，再安排小图机制门和有限预定条件实验。

M1–M4 中不依赖该理论的执行/效果工作可以在恢复后推进；正式风险界与模式 Pareto 主张
需要 T 完成。EXACT向权威模拟用户澄清，现实用户不逐题参与；M0先提供可自动运行的
信息动作，再让新理论决定如何选择/计量它。不能将“无人值守”解释为禁止user oracle。
