# FinBench partial-input release candidate

2026-09-15. Continue the approved trusted, partially bound input track. Publish
actual frozen inputs and profile candidates; no formal evaluation, cohort
resampling, authored-baseline modification or new ambiguity metric.

Input is the existing resolved FinBench cohort. Preserve all groups, original
question text, split/exposure and post-seal reference pins. Only a relation label
designated by an explicit family rule becomes one predicate hole. Repeated uses
share that binding. Dates, IDs, directions, node types, filters, aggregation,
projection, ordering, limits and graph structure are unchanged. Binding the
declared authoritative candidate must reconstruct the original entire program.
No target, prediction, group or distractor is chosen from answer emptiness,
method results or measured execution costs.

This is an authored derived schema-grounding input, not official FinBench NL
coverage, natural ambiguity prevalence, or arbitrary-NL structure validation.
Source assignments are explicitly supplied from the existing authored semantic
input, equally available in the shared profile. This condition cannot measure
source-discovery accuracy. External author engines retain their own interfaces.
Do not pool this with the resolved track's online schema-routing cost.

The initial candidate freezes the same three relation candidate IDs and the same
available model/authority actions for both modes. No hand-written predictions or
hidden authority is put into the initial binding state. The model is untrusted;
the authority is the declared authored semantic annotation accessed on demand,
not a query-answer lookup. Its actual file cost is charged; no human-delay claim.
Model prompt/provider and budget are pinned. Unknown action estimates remain
null. Initial order and budgets are development candidates, not paper defaults.

EXACT validates the slot; PERFORMANCE may accept its unvalidated model proposal.
Failures remain declared branches and outcomes. No current-query execution,
answer read or tool call during publication. Catalog/estimator are admitted from
their existing frozen artifacts, never rebuilt or fitted. Publication records
one-time metadata cost. Native gets the two XGAP methods; same-facts RDF gets the
explicit six-method v2 study. FedUP's known generated-form limitation is retained.

Allowed files: one partial publisher/CLI, candidate policy, optional question-pin
admission for templates, targeted tests and current docs. Legacy unpinned partial
templates remain usable. An explicitly pinned template must reject changed NL
text before any acquisition; closed templates still require a pin.

Acceptance: exact reconstruction, repeated-hole consistency, unchanged literals
and denominator, no answers opened, no fabricated predictions, same candidate
sets/mode permissions, pinned authority/query, explicit source-information scope,
zero calls/builds/fit during publishing, unchanged old cohorts. First check small
metadata fixtures and at most the first development input of each family for
new plan-availability risks; do not run large-data execution to debug this step.

RQ: cost/quality of information acquisition and estimated physical planning for
the same trusted partial query. X: mode/method and predeclared information
condition. Y: strong-plan availability, paid acquisition, planning/online cost,
correct completion. The release still needs actual development cost/availability
assessment and the paper protocol discussion; a manifest alone is not readiness.

MaterialPassport: implementation and reproducible candidate inputs, no new
accuracy/latency result, no changed research scope or formal campaign release.
