# Chapter 7: separately reported sampling frames

2026-09-21 用户明确批准“采用双分层，分别报告”。这修订正式实验的取样总体，
不修改已冻结 pilot，不按答案或方法胜负重选题。原三数据集/E1–E20计划继续有效。

## FinBench 的可执行定义

|报告分层|账户锚点资格|公司锚点资格|
|---|---|---|
|全 ID 均匀取样|冻结源中所有账户 ID|冻结源中所有公司 ID|
|活跃锚点取样|至少一条出向 TRANSFERRED_TO 边|拥有至少一个有入向 TRANSFERRED_TO 边的账户|

资格只读取边的两端和 ownership，覆盖整个冻结源的时间范围。不读取金额、封禁状态、
题目的时间窗口、私有意图、参考答案、耗时或任何方法结果。平行边不增加抽中权重；
self-loop 也算结构活动，因此选中后仍可能因 acyclic、时间或属性条件而得到空答案。
不能保证非空，也不要求非空。缺失端点/owner 视为源完整性错误，不静默删掉。

两个分层准确地说是两个有重叠的抽样框，并非互斥分区。各自以独立固定随机流抽取，
不从 active 框排除已被 uniform 框选中的锚点，否则会改变 active 总体。每个框内，
三个结构等额，锚点等概率无放回；两种账户结构使用不同账户。之后独立均匀选择四个
源时间季度之一、16 个合法 intent 之一。选题与 private intent 编号在参考计算之前封存。

沿用已有 account/company 的 pilot/formal 分组；同一类型/ID 的所有窗口、intent、
重复、方法和跨框出现共享 family group ID。所有正式选题仅使用 formal fold。
随机种子、框的完整 ID 清单及哈希、各框/类型可选数量、跨框重叠都保存。

## 报告约束

- 分层各自报告 E1–E20 的适用面板、分母、空参考比例、失败和非回答。
- 不将两个分层简单合并为一个整体优势结论；active 总体不代表全 ID 总体。
- 对同一锚点的重复与跨框出现按 family 聚类；不虚增独立样本数。
- 质量统计保留全部请求；耗时使用预定共同完成集合，同时报告集合大小。
- 活跃资格不是模型/规划器的意图权威。私有答案与意图仍只经计量接口披露。
- 该批准不授权挑选更高 speedup、更大非空答案或 Performance 更有利的题。

新实现为 `chapter7_finbench_strata.py`，只负责资格和取样；它既不执行 query，
也不调整 planner。正式样本量、重复、扫描水平与 study 总预算仍需在正式结果打开前冻结。
Freebase/FedShop 使用各自图上的同类结构资格，并在其数据接入后明确记录谓词/方向。
