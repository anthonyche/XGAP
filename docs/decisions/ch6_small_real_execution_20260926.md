## 有效 probe 的定义

新的 live registry 在实际 NL 候选和合法 seed plan 形成后绑定，而非提前把某个
controlled family 的候选权重赋给不同的模型输出。目标是源版本固定的单 Match
编译片段，COUNT 上限为 threshold+1；不是扫描量或执行耗时的上界。

配置显式采用 expectation、实际公开候选上的均匀先验，以及含 unknown 分支的
声明分类成本模型。先验行数等于结果类别的期望行数；因此没有可变物理选择时，
不能仅靠“看见较小数值”制造 probe 的价值。目标按候选/算子绑定，不把一个统计
无差别用于整个后端。unknown 不重试，必需完成证据不被可选 probe 替代。

修复了一个真实门控错误：`gates_rule=None` 曾与没有 rewrite 的 seed 的空规则
相等，从而把可选统计动作误当作 seed 的必需能力证明。

XGAP/NP 的配置仅 probe 可用性不同；注册数、实际选择数、结果类别、费用和最终
计划分别记录。独立 NL 调用可能产生不同候选族，必须记录族身份；只有相同族与
相同源上的配对才能解释为 probe 的因果对比，不能仅根据方法标签假设它们相同。
数值分类成本/概率是预先声明的工作模型，未校准成真实时间；实际时间、token、
调用、字节仍独立测量。高价或无价值的 probe 应当跳过。

本地真实 Neo4j/Fuseki 的各一个小图 COUNT 已通过生产观测器，共两次转发、零失败，
服务已关闭。另一个已有八候选公开 NL family 的零外部调用分析注册了四个目标，
但 D=2 的一个公共符号分支选择 transform→transform→terminal，没有购买 probe。
根状态触及 action cap 后退到必要验证，部分分支触及可选规划时限。这说明通道和
动作已存在，不证明本批一定观察到 NP 差距；实际选择率及 cap/deadline 事件都应报告。
没有为强迫获胜调整先验、价格或深度。

上述两个独立证据分别为 `ch6-live-probe-native-20260926-v2/receipt.json` 与
`ch6-live-probe-public-lookahead-20260926-v2/receipt.json`（位于外部 xgap-data 目录）。

## 预算和指标

主批次最多六小时，CPU 8 核/24 GiB，不固定节点、不申请 GPU，沿用 LLM API。
模型调用保留上限 1,728（192 个内部请求各一次、24 个外部请求各最多 64 次）；
认证检查单独计量。输入/输出 token 停止阈值为 6,000,000/1,000,000，逐请求前
检查，当前请求可能跨过阈值；不假装拥有未验证的 tokenizer 严格上界。
总实验存储检查上界为 160 GiB，另留 6 GiB；这是停止上界，不是预先占用空间。
每题原有源/方法限额不放宽。

平均消耗包含所声明总体内失败的实际消耗；延迟分别给完整回答、失败和截断的
覆盖与分母，不能把快速失败算作快速答题。调用/token/字节/CPU 秒可加总或取均值；
峰值 RSS 按请求统计，不能乘题数。若另做总量预算推算，保持与实测表独立。
未运行、不支持、截断和缺失量均保留明确状态，不补零。
