# T5 current-system batch boundary — 2026-09-20

The user authorized this engineering while designing Chapter 7. No new research
distance, search algorithm, workload, baseline optimization or full campaign is
part of this milestone. T3 remains immutable. T4's core claims remain unchanged.

## Interfaces

- Current method IDs: `xgap-bounded-joint-exact` and
  `xgap-bounded-joint-performance`. Historical IDs retain historical behavior.
- Common NL worker/trial accept separately pinned public `scope` and `joint_config`
  alongside request/profile and private `oracle`. Reference rows are never a worker
  argument. Each common receipt verifies all these identities.
- Config schema `xgap-bounded-joint-run-config-v1` freezes information policy,
  search limits/resources, declared joint costs, proposal provider and epsilon.
  Exact uses epsilon zero; Performance uses the frozen epsilon. Budgets are not
  silently inherited from historical user-call flags. All other settings are shared.
- Default provider is the frozen compact LLM. An explicitly labelled
  `development_toy_template` uses the repository's public toy grammar and permits
  only requests whose exposure is `development`. It has zero model calls and is
  not evidence of model effectiveness. It never reads private intent to propose.
- Common scorer reads raw or gzip answer pins with stored and logical hash/size
  checks. Answers are compared only after a common outcome is sealed. Order and
  multiplicity are retained; corrupted evidence is a comparison error, not a match.

## Batch execution

`scripts/run_bounded_joint_batch.py` accepts a SHA-pinned
`xgap-bounded-joint-batch-v1` manifest. Fields: `deployment` (`native` or `rdf`),
`prepared`, `design`, `cells`. `design` explicitly declares total wall time,
package bytes, free disk reserve, worker wall/RSS, source RSS, startup timeout and
`SourceObservationBudget` including compression. Each ordered cell has unique
`cell_id`, current `method` and absolute SHA-pinned `request`, `scope`, `oracle`,
`config`, `reference`. This schedule is provided by an experimental release, not
generated by the runner. The runner does not change prompts, K, stores or estimators.

Sources use owned serving copies of frozen stores. Startup is offline preparation,
and scoring is post-seal evaluation; both are outside common per-method online time.
Budget/observer/cleanup overhead inside the common trial remains measured. Actual
calls/tokens, planner CPU, certificate time, execution time, wire bytes and disk
bytes remain distinct from declared estimated cost. Results do not imply an output
error guarantee or improvement in end-to-end latency.

## Resume contract

The output identity pins manifest and clean source commit. A process lock prevents
concurrent invocations. Every attempted cell gets an exclusive intent before worker
launch. Sealed success and failure both count as attempted; incomplete intents are
reported separately and never automatically retried. Resume runs only unattempted
cells and verifies earlier outcome/score identities. No old result is overwritten.
If a previous invocation lacks verified resource closure (e.g. hard kill), resume
refuses until explicit recovery; it cannot assume orphan sources stopped.

Study budgets are sticky once observed in an invocation, and primary study
censoring is preserved over secondary transport errors. Total wall time counts
elapsed time since first invocation, including pauses. New invocations start fresh
source sessions and record that cache condition. A successful phase can reuse its
owned session within an invocation; a failed phase must close it. The manifest must
declare the intended order/cache protocol before paper evaluation.

Validation: focused boundary tests, then a bounded native toy batch using the real
common subprocess, scorer and resume path. No SF0.1 campaign or SOTA comparison is
authorized by this gate; final acceptance evidence is recorded separately.
