## 第一轮真实 pilot

- 范围：现有完整 D1 native 24 题、RDF 32 题，各执行 repetition 0。
- XGAP/NP/SH/GR 各 56 次、TS 32 次，共 256 次方法请求；native 的 TS 不支持状态保留。
- 顺序：native/r0 → RDF/r0，单元内部沿原 manifest 的方法顺序，不按结果选题或换题。
- 明确标记 development pilot。历史请求中的原 exposure 字段保留；研究用途由新的
  pilot release 和结果回执明确覆盖，不能引用它们证明未用于开发的最终测试成绩。
- CPU batch，8 核、24 GiB；不固定 compt311，不请求 GPU；使用既有外部模型 API。
- 单次方法 300 s、方法 3 GiB、源 4 GiB、单次源请求 60 s 等原合同不变。
  超时作为结果保留，不再以逐题优化或增加重试为准入条件。

独立入口 `run_ch6_dataset_pilot.py` 只接受从已发布回执中原样选出的两个首轮单元，
不要求先完成整套 21 图的正式 workload。`audit_pilot` 核验冻结输入、完整支持子集、
双部署、资格、参考、现有配置、磁盘及预算；不能省略基线或把某个重复轮次替代 RDF。
没有改变 planner、baseline 算法、prompt 或解码设置。

## 冻结预算与实际执行边界

|项|本轮合同|
|---|---:|
|pilot 总墙钟|14,400 s（4 小时）|
|Slurm 时限|4 小时 15 分钟，含收尾归档|
|保留证据与当前服务副本空间预算|64 GiB|
|启动前与执行时可用磁盘保留|6 GiB|
|最大模型调用总数|2,272|
|输入 token 停止阈值|4,000,000|
|输出 token 停止阈值|5,200,000|
|单次共享源会话最多方法请求|32|
|重复 / 自动重试|1 / 0|

2,272 来自 224 个内部方法请求各至多一次，以及 32 个 TS 请求各至多 64 次。
该数是保守调用上限，不是费用或实际耗时预测；观察预算可能使整轮提前停止，
届时保留未运行项及覆盖率，不能称 256 次全部完成。

**token 是观测停止阈值，不是未经验证的输入 tokenizer 上界。** 每道方法请求前
检查已封存的 provider usage；当前一道方法请求可能越过阈值，TS 的一道请求可能
含多次模型调用。这种超出会如实记录；没有精确 tokenizer 时不声称严格 token 零超额。
实际调用、请求/响应字节及时间仍受原有 transport/worker 合同约束。
任何缺失用量或未封存请求都停止后续工作，不当成零，不自动重试。

新增 `before_cell` 仅用于 supervisor 的计量检查；它在创建下一次尝试和启动服务前
生效。停止后正常关闭共享源会话，保留已完成及失败结果。不会为了每题检查预算而
强制重新装载数据。正式 campaign 原入口和默认行为保持不变。

## 正式 workload 补建

1. 现有 176 题及已调试模板保留为开发/诊断证据，不能重新命名为独立最终测试。
2. 固定 benchmark 原版本、文件 SHA、原始 query ID、完整 query 和类型化结构。
   领域派生须逐项记录关系/类型/过滤/聚合/投影/排序/截断的映射与修改。
3. 在共同 compact IR 上比较所有已曝光开发模板与新模板；仅换实体、参数或变量名
   不能变成新测试结构。通过编译、独立参考和小图语义检查后才准入领域模板。
4. 按 W1–W4 和 uniform/active-anchor 分层，在方法结果之前冻结实例取样。
   原每域每 W 层 200 题仍为初始目标；依据模板覆盖、pilot 方差和预算确定最终数量，
   若要缩小范围需明确告知用户并确认，不能以重复执行数代替题量。
5. 固定样本的真实执行超时保留，不按 XGAP 胜负、答案是否为空或基线质量筛题。

本轮已完成源码取证入口：验证 LC-QuAD 原始 Git blob 及父树，以预先声明的源行
区间 `[128,640)` 抽取，不读取任何方法结果。1,024 条源查询记录中 476 条命中已有
源结构，479 条按已有语法范围拒收，69 条属于 20 个新源结构，等待领域准入。
这些不是 69 道已经完成的正式题；跨 IR 的开发结构重叠检查仍待领域 lowering 后进行。
此前已提取的 43 个源结构全部作为曝光记录保留。
