# 可查询的权威模拟用户 — 设计修正，2026-09-16

状态：用户已明确要求此能力；本次仅修正文档，尚未接入当前 NL profile。此前“暂时不要
开始执行”的指令继续有效。实现、测试、模型调用与新实验等待明确恢复。

## 用户要求及此前误解

用户本人不逐题回答或做 validation；系统必须提供一个持有权威信息、可以 query 的
模拟用户。EXACT 需要 clearance/clarification 时向它提问，得到回答后继续，不应因为
现实用户没有在线回应而返回失败。

先前将“无人值守”解释成“不允许逐题权威 fixture/用户角色”是助手的设计误解。
该限制现在撤回。权威意图可以来自 gold semantic query/意图标注，只要明确作为
模拟用户的私有知识，通过声明的交互接口供系统询问。这是模拟交互的实验设定，
不是把模型置信度伪装为权威，也不代表已测得真实人类交互表现。

## 知识与接口边界

模拟用户维护冻结 `intent_state`，可由已有 gold 语义自动构造，包含真实实体选择、
关系/方向、时间范围、过滤条件、聚合与排序意图等预先声明的信息。不要求现实用户
再逐题填写回应。它也可以持有完整目标语义；不能因此让 planner 在初始输入中直接读取。

第一版采用确定性 oracle 即可，不要求再部署一个 LLM。若以后用 LLM 将回答自然语言化，
权威内容仍由固定意图状态决定，不来自该 LLM 的猜测。

拟议交互：

1. planner/解释器提出具体澄清，例如“这里的 Alice 是哪个实体？”或“时间条件是否
   只作用于转账边？”，并声明本次询问的语义范围。
2. oracle 从私有意图状态回答，返回 scoped response、版本/来源以及本次交互记录。
3. XGAP 将适用范围内的回复作为权威观察，消解相应不确定性，继续更新策略与最终计划。
   模型产生但已被用户明确否定的绑定不能继续当作正确意图使用。
4. 信息充分后执行一个最终联邦计划；答案仍由独立评分器检查。

不能只支持当前显式 hole 而忽略结构/字面值中需要澄清的意图。可以验证具体语义陈述，
但接口需限定可回答的语言与范围；不把任意查询等价判定作为 oracle 的隐含实现要求。
如果候选列表没有正确选项，必须允许“均非/给出正确值”的声明结果，不能强迫模拟用户
从错误候选中选择。后续处理和候选扩展仍需有限、有界，不能无止境生成。

完整意图确认若作为一个动作，必须预先声明其信息范围并记录成本；不能把“问一个字段”
的回复暗中扩成整份 gold query。oracle 不提供最终结果行、gold 物理计划、最优源分配或
当前题候选运行时间；那些不是本角色用于表达需求的权威信息。

## 规划与 strong 条件

oracle 是可查询的信息动作。策略可以根据已收到的回复继续选择动作；构造候选、
符号化 AND/OR 搜索和代价估计不能提前读取本题隐藏意图或偷偷调用 oracle。
所选动作的声明结果需有相应后续，运行时取得真实回复并走该分支。

在声明的意图范围内，实验发布前检查 oracle 信息完整性、响应一致性和可达性。
需要求证且预算允许时 EXACT 应继续询问，不把“现实用户未回复”当失败路径。
若缺少应有的权威字段，应在准备阶段报 oracle/数据配置缺口。实际传输故障、预算耗尽、
不支持语义或后端失败仍分别记录；模拟用户存在不意味着所有图查询都能执行。

oracle 的权威作用只覆盖已经询问并确认的部分。不能由一个实体回复宣称整个 NL 意图
已验证；后续程序变更使旧回复失去适用性时需要重新核对范围。完整意图是否已获得确认
与执行计划是否 strong 要分开报告。

## 成本与公平比较

- 记录澄清次数、请求/回复、透露的信息范围、oracle 处理时间以及实际模型/网络费用。
- 本地 oracle 查表耗时、人为设定的用户等待成本、真实端到端时间分别报告。任何模拟
  时延/收费都在协议中预先声明并同等适用；不能加等待来强迫 EXACT 输给 Performance。
- 两模式获得相同 oracle 接口和信息权限；是否询问、询问多少由各自策略与预算决定。
  这使用户正在推进的信息—精度权衡有可执行对象，但尚不证明其收益或 d/risk 界。
- NL 外部组合方法若进行交互比较，应拥有相同 oracle 权限，使用预先固定并公开的
  前端交互规则；作者 FedX/FedUP 引擎不改。组合方法不能冒充作者原生 agentic NL 系统。
- 固定语义的执行轨继续同查询比较，不加无意义澄清。新的交互轨标为
  `NL + simulated-user interaction`，与旧 `NL-only`、可信模板轨分别记录。

## 恢复后的最小验收

新增 M0 模拟用户接线，复用已有权威证据/信息工具边界；不重建通用对话产品。
先在小图验证：单槽、多槽、结构陈述确认、错误候选拒绝、含正确替代值的回复、
证据范围、有限预算和 oracle 配置不完整。保持一条 NL → 询问模拟用户 → 意图更新
→ strong planning → 单次最终执行 → 自动评分的完整 slice。

必须观察到一次真实的工具询问和权威回复，而非预先将 gold 写入方法输入。满足范围与
预算条件的澄清例应无需现实用户参与而继续形成可执行计划，并返回参考一致的结果。
同时保留 oracle 调用和模拟费用的独立账本，不把未发生的人工时间当测量值。

当前已封存的 72 个方法观测没有接入此模拟用户，其运行事实与分数保持不变；不能将
它们重新标为交互系统评价。旧报告中禁止权威模拟用户的表述已标记为被本设计修正覆盖。
