# Common method trial v1 — 2026-09-13

Purpose: make approved RDF efficiency/effectiveness comparisons executable with
honest common inputs, outcomes and resource boundaries. No baseline algorithm,
answer, summary setting, population, prompt or estimator weight changes.

Allowed implementation: fixed-semantics worker for XGAP/FedUP/FedX, common outer
record/scoring, schema-only source routing, owned-service accounting and cleanup,
small new-risk tests and a necessary tiny boundary. No large-data debugging or
repeated baseline readiness gates. NL quality and trained-estimator evaluation
are not measured by this component milestone. Shared NL-to-external-SPARQL lowering
remains required later; do not claim an NL baseline exists from this fixed input.

Fixed input carries a pinned semantic program and unresolved public SPARQL for
the same declared question, plus question/dataset/population identity. It has no
reference rows or source assignment. XGAP derives Match source eligibility solely
from frozen source schema and uses a stable source choice when identity stubs are
declared in more than one source. Required projected/predicate fields must all be
available together. This v1 source router rejects non-Match remote operators and
unresolved holes explicitly; it does not claim all global semantic forms.
FedUP/FedX receive the unchanged global SELECT; no injected SERVICE/VALUES/source
choice and no XGAP answer/coordinator completion around the baseline.

Common subprocess guard includes process startup, frozen input loading, ordinary
planning/execution and durable worker records. Each top-level method is invoked
once; candidates are only estimated. No gold/reference access before sealing.
The supervisor keeps failure identity even without a worker receipt. Full outer
time ends after durable outcome sealing; final benchmark timing telemetry and
post-seal reference evaluation are separately measured, not recursively included.

Observe source request payloads at the same proxy boundary for all RDF methods.
Hosted-method and source-process RSS/CPU are sampled separately from the worker;
do not add separately sampled peaks and claim a simultaneous physical-memory peak.
Only processes actually created and owned by the caller may be monitored/stopped.
If worker/host/source/observer fails or exceeds its declared bound, stop all owned
method and source groups, preserve the outcome, and require a new serving session
before another query. Worker termination alone and an empty HTTP observer queue
do not prove server-side quiescence. Recovery cost is explicit; no failed query is
retried. The campaign controller must retain unrun cells and resume distinct cells
only with a newly verified session, never label them method failures or zeros.

Financial score converts declared SPARQL literal columns to the same predeclared
text/integer/decimal3 contract as XGAP JSON rows. No URI/language coercion, sorting,
deduplication, best-of-reruns or output-derived normalization. Order-aware exact and
multiset F1 are computed after raw output sealing. Failure against empty gold is
zero. Wrong-but-returned output is distinct from transport/parse failure.

Acceptance: new schema routing/score equivalence risks, subprocess terminal failure
retention and real owned-service cleanup with an unrelated process left alive;
one tiny common-runner boundary only. Existing accepted core/baseline gates remain
accepted. Formal population, offline summary and common NL adapter readiness must
be reported separately before campaigns.
