# T2：有限意图证书接入共享 strong policy

2026-09-17。用户授权继续优化、完成接线，并使可检验的 Performance tradeoff 显现。
实现使用 T1 的[有限意图距离与覆盖契约](finite_intent_discrepancy_v1.md)，不改代数。
本文件替代 T1 中“主入口尚未接线”的当前状态描述；T1 的逐槽算法与历史证据保留。

## 契约与入口

新增 `xgap-nl-family-exact` / `xgap-nl-family-performance`，经主 NL API、CLI worker、
共同 supervisor 调用已有 `search_strong_policy`。旧 NL-only/user 入口与 baseline 算法
保持原行为。新入口明确接收 **NL + 独立冻结的公开完整意图家族**，并非开放 NL 评价。
公开家族不能包含哪一个候选是真实意图；单独 pin 的私有模拟用户保存真实选择。
双方共享 source snapshot、家族、metric、动作、调用/披露/搜索预算与候选顺序。

Exact 的 epsilon 固定为零；Performance 使用预先声明的 epsilon。每个状态先对仍与
已收到权威信息一致的候选检查 `max d <= epsilon`，仅认证后才准备物理计划。
未知覆盖、硬字段冲突、预算内无完整策略时不产生无证答案；oracle/后端不可用照实失败。
这里 safe non-answer 是真实预算或契约失败，不是等待现实用户在线回答。

公开家族完整性是应用/实验的权威前提；LLM top-K 不构成覆盖依据。可选共同 NL proposal
最多一次，不删减意图 support，也不提供 authority。当前 profile 的规划输入是公开家族，
不是该 proposal；启用它只验收模型接口与费用保留，不能声称验证了自由 NL 解释准确率。
可显式关闭该共同前端；本轮不声称在启用情况下减少其调用/token。开放 NL 的范围获取、
LLM/probe 的联合按需策略、factorized support 都仍是后续工作。

## 相同动作空间与完整 AND 后续

OR 中始终提供 full-intent（全部槽）、单槽以及配置允许的有限多槽询问。默认每次交互
计一单位；可另冻结按实际披露槽数计费。单位是声明信息负担，**不是毫秒/真人等待时间**。
预算同时限制调用数和披露槽数。不能为了制造模式差异删除 Exact 的便宜完整询问。

每个 action 按公开 support 划分全部可能回复。共享 solver 先构造一个完整 strong
incumbent；选中 AND 动作每个回复都必须有可编译且满足契约的后续。搜索只构造符号
回复，不调用 oracle 或数据库。运行期只调用选中策略的实际 action、匹配真实回复分支，
重新检查 terminal certificate，最多执行一个最终联邦计划。无多计划试跑选优。

完整询问作为可行策略 seed。若某个 action 自身声明成本已不低于当前完整策略成本，
因后续成本非负可剪去其展开；只对声明目标成立，不是实际时延最优性证明。
认证 terminal 立即停止进一步信息搜索和物理 refinement。物理准备按候选缓存，失败也
缓存，同一请求最多 K 次。完整后续包含多份编译计划，不等于执行多次查询。

私有模拟用户只返回所问字段；私有文件带随机 nonce，防止通过公开 hash 穷举识别
少量候选中的真实选择。预检只确认文件/schema/家族/问题身份，不向 planner 披露选择。
记录真实调用、字段数、回复字节及本地处理时间；不注入虚构人类等待成本。

## 目标与多项式界

此 profile 的策略目标为声明信息负担的最坏分支和：
`V(action)=cost(action)+max V(outcome)`；terminal 的未来信息负担为 0，**不是执行成本为零**。
物理候选采用冻结的 path-depth/edge-count 相对工作量顺序，只有满足证书者可入选。
这是未校准的结构启发式；尚非学习估计器或 acquisition+execution 联合时延最优。

令输入字节 B、候选 K、槽 m、全局状态上限 S、action 上限 A、每状态公开scope数
L≤m+32、编译成本 C(B)。距离表 O(K²m)，当前checker逐候选重新检查support，
每状态证书保守上界 O(K²m)。每scope划分/排序回复 O(Km log K)，包含未产生action
的无信息scope检查；候选物理准备总计不超过 K·C(B)。忽略定长hash常数，上界可写为
O(B + K²m + S(K²m+LKm log K) + AKm + K·C(B))；状态/回复还乘其有界编码长度。
权重、分数位长、输入大小、缓存、S/A/H 都受显式限制。强策略输出亦受 S 约束，
无需枚举无界组合；有限深本身不是 PTime 证明。最终数据库执行的数据复杂度另计。

当前 K≤64、m≤32、S/A≤4096、H≤32；默认 S/A=128、H=4，每 action 最多16个声明
结果（配置最大256），所以 K 大时须在运行前相应设置 outcome/state 预算，不能截断回复。
如果所有 K 个查询可执行、完整询问/回复可用、预算容纳 K+1 状态及全部 outcomes、
一次完整披露和各后端计划，并且编译在期限内完成，则一问 seed 能形成完整 strong policy。
不足时保留已有完整 incumbent，否则 safe non-answer。deadline 是合作式检查，不能
抢占正在执行的编译；没有全局最优、常数近似比或非零 root-gap 证书，gap 保持 null。
T1 的“同一逐槽 fallback 前缀不更长”定理不自动推广为此启发式搜索的全局比较定理。

## 机制验收及可失败的假设

已知8节点上冻结5个相近意图、4个等权软坐标；全量候选及完整询问对双方开放。
中心候选最坏半径1/4，单坐标变体最坏半径1/2。固定真实意图为中心：
Exact 一问恢复中心；epsilon=1/4 直接选中心；epsilon=1/2 可选更短查询。
答案差异由执行后的独立参考评分，不能把意图界解释成答案误差界。

必须保留负例：epsilon=0、硬跳数、低搜索预算、某反事实分支不可编译、完整询问便宜时
无进一步询问信息收益。另以两独立槽案例验证“先问一个，再认证停止”，避免仅验证根停止。
OR 更多只有在存在值得跳过的确认/搜索工作时才可能有帮助，可能反而使证书更保守。
不复制分支、不加无用动作、不放大 Exact 费用、不修改 baseline 来制造优势。

本轮仅定向单元/模块与小图机制门，再做至多两次模型调用、两次原生最终执行的 worker
接线验收。无规模扫测/统计显著性/SOTA 胜出主张；材料和结果见
[T2 报告](../report/strong_intent_20260917.md)。
