# Ordinary financial NL profile on the accepted tiny facts

RQ: does the ordinary one-shot input carry a financial question through frozen
grounding, estimated physical choice and necessary native federation? X is the
new financial schema/input profile; Y is stage completion, exact ordered answer,
actual model/source calls and separated offline/online cost. This is a development
boundary, not a mode comparison, accuracy estimate or speedup experiment.

Allowed changes: the offline profile publisher, one tiny NL request/reference,
owned-service runner, two focused input checks, and current evidence documents.
No planner/estimator retraining, baseline changes, repeated accepted queries,
large-data debugging, current-question probes or automatic retry/repair.

Reuse the pinned 8-entity/16-edge financial mapping and the unchanged32-sample
frozen deployment from be22cb8. Generate schema from source placements, all entity
names from the snapshot and a finite scalar catalog; there is no query or gold
program input to publication. The two sources share canonical node identity and
types; only graph has edges/profile fields, only control has control attributes.
This is source schema, not a gold per-operator assignment. Entity selection remains
prediction, never authority. File hashes bind the loaded snapshots and model.

Freeze both ordinary mode configurations, preserving K1/K3 and existing budgets.
The actual first request uses performance, with the existing generic financial
syntax prompt and thinking disabled. It supplies only original NL and reusable
schema/runtime identities, without prepared operator IDs, required-constraint
objects, expected rows or target queries. The request describes the already
exposed financial tiny task; retain that exposure and never label it held-out.

Publish before inference. The ordinary runtime reads frozen artifacts and never
builds catalogs or fits models. Start isolated local Neo4j/Fuseki and load the
existing pinned tiny bytes once. Submit one model request and at most one final
plan. Capture all actual backend artifacts/responses and seal the result before
independent answer scoring. The reference uses direct fixture arithmetic and was
authored before the model request. Native snapshot ownership/loading, health,
publication and startup costs are separate from online latency.

Acceptance: both frozen modes pass the new input boundary checks without calls;
the one actual request preserves its complete success/failure and usage. An exact
answer from required Neo4j/Fuseki contributions would accept this live financial
NL slice. A model failure is evidence, not permission to substitute the gold
program or retry; diagnose the saved response locally. Neither outcome by itself
establishes model quality, estimator ranking or paper evaluation readiness.

Actual v1 outcome: one1970-token response failed the unchanged parameter admission;
zero final queries. See [evidence](../report/financial_nl_20260912.md). Static replay
identified missing full row-operator guidance in the envelope-only wire prompt.
An explicit v2 syntax option now adds generic aggregation/order/identity/source
rules. It leaves v1 as the default, changes no runtime semantics, and has new wire
budget checks only. The next actual v2 boundary must preserve the original failure
and exposure; no runtime repair or automatic version fallback is introduced.
