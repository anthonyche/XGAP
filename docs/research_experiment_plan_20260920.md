# XGAP 实验执行计划

## 1. 任务与范围

建立可复现的实验流程，评价 XGAP 在查询语义和执行信息不完整时的成本、答案质量及联合决策收益。使用 **FinBench-derived、GrailQA/Freebase-derived、FedShop-derived** 三个数据集，三者执行相同实验矩阵。

产出 **20 张图：正文效率/成本 6 张、有效性 6 张、消融 3 张、真实 policy 案例 1 张；附录可扩展性 4 张**。所有定量图只有一个 X、一个 Y、一个研究问题；每张图的三个数据集面板使用相同坐标定义。绘图使用 Matplotlib，保留原始数据、汇总数据和生成脚本。

本任务不要求改写外部算法、扩大 XGAP 的理论保证或为了得到优势调整测试集。发现实现缺口时报告具体模块、影响实验和错误证据。

## 2. Research questions

| RQ | 问题 | 实验为什么需要它 |
|---|---|---|
| RQ1 | XGAP 在可比部署下的端到端耗时和数据传输成本如何？ | 检查联合规划的开销及实际成本，避免仅报告估计目标值。 |
| RQ2 | 面对歧义请求，XGAP 的答案正确性和回答覆盖率如何？ | 区分正确回答、错误回答和拒答，防止把快速失败当作效率收益。 |
| RQ3 | Performance 相比 Exact 能节省多少获取与处理成本，伴随怎样的质量变化？ | 检验允许有限语义偏差是否带来实际收益，而不只是减少验证要求。 |
| RQ4 | 执行代价反馈是否改变信息获取，并降低总处理成本？ | 用共享组件的消融隔离联合决策；外部系统比较本身不能完成机制归因。 |
| RQ5 | 候选数和源端点数增长时，系统开销如何变化？ | 分别检查策略搜索与跨源协调的规模限制。 |

epsilon 是应用允许的损失上限；语义歧义程度是请求进入规划时的难度。二者分别扫描：前者检验容忍度的作用，后者检验在相同容忍度下系统能否处理更难的请求。歧义实验支撑 RQ2/RQ3，不另立 RQ。

跨平台结果回答异构执行场景下的问题；RDF 外部比较回答相同 RDF 部署中的系统竞争力。**单源 RDF 结果不能证明联邦执行或跨平台优势。** 若没有可运行的外部方法，明确保留外部比较的证据缺口，不能称已优于强两阶段系统。

## 3. 方法与公平比较

### 方法

- **XGAP-Exact、XGAP-Performance**：共享候选生成、编译器、物理候选空间、执行器及资源限制。Exact 满足规定的验证条件；Performance 采用相同硬约束和已验证绑定，仅按冻结的 loss 定义与 epsilon 放宽允许的选择。
- **无执行代价反馈消融**：分别对两模式关闭执行代价对信息获取与停止选择的影响；保留最终物理规划、合法性检查、动作、候选和预算。并列选择规则固定，不访问隐藏 intent。
- **外部方法**：优先验收作者发布的 [ARUQULA](https://github.com/AKSW/ARUQULA/tree/aruqula) 与 [FedUP](https://github.com/GDD-Nantes/fedup)。前者是 text-to-SPARQL 方法，后者提供 SPARQL federation 接口。仅在原生接口可连接时组成两阶段流水线；不能预先声称组合已复现或普遍 SOTA。

### 外部方法的允许改动

允许官方安装、依赖配置、端点/模型地址配置、必要的协议包装和计量日志。优先通过其已有模型配置使用实验中的 Qwen 27B 接口；记录实际服务模型标识及解码参数。若需要改变算法才能接入，报告缺口，不静默替换模型或方法。

**不修改**外部方法的提示策略、探索/修正流程、搜索策略、代价模型或优化器；不添加 XGAP 的澄清、查询修复、重排和缓存优化，也不删减原方法能力。保留配置及兼容性补丁，以便检查。必要的接口代码不得重写查询、补答案或注入 gold。

### 部署

| 部署 | 用途 | 公平性要求 |
|---|---|---|
| Neo4j + Fuseki | 三个数据集的主要实验、内部消融及真实 policy 案例 | 相同事实、分区、机器资源和缓存条件。外部方法若不原生支持，报告缺失，不为其开发跨平台适配器。 |
| 原生支持的 RDF 部署 | 外部方法与 XGAP 的端到端比较 | 所有方法使用相同 RDF 快照、端点集合、请求和资源。多端点组合必须真实执行，不能只返回计划。 |
| 单源 RDF（若外部方法仅在此可运行） | 同设置下的端到端成本与答案质量比较 | 所有方法均访问同一 Fuseki 数据集和单一源端点；不能拿它与 XGAP 的多源耗时比较。未实际使用 FedUP 时不得以 ARUQULA+FedUP 命名。 |

先冻结一种实际可运行的 RDF 外部比较设置，在三个数据集上采用同一协议；不默认复制所有内部参数扫描。跨部署结果分别成图面板并明确部署标签，面板只能重复相同 X/Y，不能混算 speedup。数据表示转换须保持身份、重复、时间和结果语义；转换、装载、索引及官方 summary 构建成本另表报告。

所有方法获得相同的公开请求、数据访问权限和可用元数据；不能只向 XGAP 提供人工解析的约束或 source assignment。方法自行使用这些信息的方式可以不同。私有 intent 只由模拟用户通过计量接口披露；不向不具备澄清能力的外部方法额外添加该能力。

### 缺失与失败

- 部署能力不支持：记为 `UNSUPPORTED`，保存原因和接口证据；相应图不画该方法，图注或能力表说明缺失，不记零耗时或零正确率。
- 环境尚未接通：记为 `SETUP_ERROR`，报告依赖/配置错误；不能称为算法不支持，也不能声称该比较已完成。
- 在已支持设置中发生错误答案、拒答、超时或执行错误：保留正式记录与评价分母，不能以“不能运行”为由删除不利结果。

## 4. 数据与执行协议

1. 冻结三套图数据、查询模板、源映射、NL 请求、私有 intent 和独立参考答案。衍生歧义任务不冒充官方 benchmark 成绩。图范围不能按测试 gold 的答案邻域抽取。
2. **端到端实验**从 NL 输入计时，包含初始化、模型调用、策略搜索、信息获取、编译、后端执行和结果物化。参考查询或正确候选不得注入在线前端。
3. **受控实验**从共同初始状态开始，固定候选、证据和后端信息，仅改变指定因素；计时到结果物化。明确它不包含 NL 初始化，不用其耗时冒充端到端 latency。
4. 受控请求先等概率抽取冻结 family，再在族内等概率选取合法、去重的 intent。每个 case 在所有方法中使用相同 intent。测试取样分布不自动提供给 planner，也不改变实现的 worst-case loss 定义。
5. 每个数据集先做 20–30 个开发 case 的 pilot，验收接口、答案、日志和运行波动；据各自配对方差、预先指定的最小有意义改进和预算确定正式样本量。开发/测试按 query family 隔离；重复运行不增加独立 case 数。
6. 冻结模型、代码、timeout、总资源限额、缓存策略、重复次数和参数水平，交错运行方法。使用同一 Qwen 27B 服务；所有模型调用、探索查询和修正调用均计量。不得按测试结果调参或追加样本直到显著。

## 5. 实验矩阵

以下每行都在三个数据集上执行。外部方法仅在已验收的部署参加；缺失按第 3 节处理。

| 实验组 | 比较方法与变化因素 | 图 |
|---|---|---|
| 默认端到端比较 | 两模式；原生支持时加入外部方法。固定默认 epsilon；异构/RDF 部署分别报告。 | E1/E2/E7/E8 |
| 模式权衡 | Performance 扫描 epsilon，Exact 为固定参考；共同受控初始状态。 | E3/E4/E9/E10 |
| 语义歧义 | 两模式；固定 epsilon，设置相同的三个初始语义歧义水平，使用受控初始状态。 | E5/E6/E11/E12 |
| 反馈消融 | 每个模式有/无执行代价反馈，其余条件相同。 | E13/E14 |
| 受控成本差异 | 固定小集，三个预定执行成本差异水平；同模式有/无反馈。 | E15 |
| 实际 policy | 每个数据集按相同预定规则选一个跨 Neo4j/Fuseki 的真实运行案例。 | E16 |
| 候选数扫描 | 两模式，三个合法候选数水平，固定图和源端点。 | E17/E18 |
| 端点数扫描 | 两模式，三个源端点数水平；固定各自总数据和总硬件资源，保持答案不变。 | E19/E20 |

epsilon 可从 0、0.1、0.25、0.5 起做 pilot；语义歧义可从 1、2、3 个选择起，候选数可从 4、16、64，端点数可从 2、4、8 起检查支持情况。正式值在 pilot 后统一冻结，不用复制候选或复制事实凑规模。端点扫描采用三套数据一致的 RDF 分片协议。不做 epsilon × 歧义程度 × 候选数 × 端点数的全组合。

**语义歧义的操作定义。** 在初始确认候选族中，统计仍有至少两个不同合法取值、且尚未获授权确定的语义选择数，例如实体身份、关系或聚合条件。相互依赖、表达同一个选择的占位符只计一次；仅等待验证但只有一个合法取值的字段不计入。按语义选择的固定定义计数，不按 JSON 字段数、模型置信度或运行后的剩余字段数计数；记录具体选择及其类型。

**构造与控制。** 对同一模板和私有 intent 构造不同初始歧义版本，提供不同数量的授权初始线索；同一级别的两个模式得到完全相同的状态。初始线索表示请求或应用已有的信息，不能把一次运行中付费获得的回答免费提供给另一模式。保持 gold 查询、数据快照、后端、预算、epsilon、可询问字段集合及收费规则不变；loss 的坐标、权重和归一化也固定，不能随剩余歧义数重算分母。这是规划阶段的受控实验，不评价 NL 解析；同一基础 case 的歧义版本属于配对记录，不增加独立样本数。

**与候选数区分。** 优先在初始相容候选数相同的匹配区组中比较歧义水平，并平衡歧义类型；匹配可使用不同但经过确认的合法候选族，不伪造候选。若逐步撤除线索导致候选数自然增加，另表记录候选数与类型组成，结论只能是该歧义构造的整体影响，不能声称已隔离字段数的独立作用。四张图复用同一组运行，不新增四套 workload；三套数据均采用同一构造协议。

成本差异优先来自真实选择率/中间结果差异；如注入延迟，明确标注并对各方法一致实施，保留成本接近的对照。仅修改估计值不能当作后端实际成本变化。Exact 若最终查询和执行信息不受获取过程影响，执行代价反馈可能没有收益；如实报告，不挑选获益题替代正式集。

## 7. 计量与数据保存

- **耗时**：端到端从 NL 请求到结果物化；受控处理从冻结状态到结果物化；策略搜索时间单独记录。scalar objective 另列，不称实测 latency。耗时图使用图内所有比较配置共同完成的固定 case 集合，并在配套表中报告该集合大小和全请求失败情况；不能用快速失败计算 speedup。
- **质量**：正确完成率与覆盖率均以全部正式请求为分母；错误答案计入覆盖但不计正确。严格检查重复、排序、聚合和空值。平均 F1 将拒答/失败记 0，空结果规则预先冻结；F1 不替代严格正确性。
- **工作量**：澄清调用、披露字段、模型 tokens、后端调用按实际发生量记录，包括最终失败的请求。传输量统计后端响应正文的未压缩字节，每条传输边只计一次，含探索及结果传输；离线装载和模型通信不混入。无法可靠采集的指标记缺失，不记 0。
- **loss**：按冻结定义独立计算已执行查询相对私有 intent 的损失，保存证书和违规记录。E10 的有效样本数、未执行请求和证书检查另列表；观测最大值不等于理论保证。loss 不冒充答案 F1 保证。
- **统计**：保存逐请求、逐重复记录，按 query family 聚类计算区间；三个数据集分别报告。消融和工作量图的质量、失败率必须在配套表中保留。

每次实验使用唯一目录，禁止覆盖旧运行：

```text

  manifest.yaml             # commits、数据哈希、模型、硬件、配置、seed、预算
  capabilities.csv          # 方法×数据集×部署的支持/接入状态及原因
  workload.jsonl            # 公开请求及 case/family/variant ID、初始歧义数，不含私有 intent
  private/                  # intent、参考答案；不向 planner 暴露
  raw/                      # 逐请求事件、回答、错误、tokens、调用与计时
  policies/                 # 策略节点/边、观察 trace、原生片段、终端计划
  metrics.parquet           # run/case/method/deployment/setting/repeat 粒度
  summary.csv               # 汇总值、区间、分母
  figures/                  # E1–E20 的 PDF、预览 PNG、逐图 CSV
```

## 8. 执行顺序与验收

1. **接入验收**：冻结代码版本，逐数据集验证图映射、答案参考、Qwen 接口和后端执行；完成外部方法能力表，记录所有兼容性改动。
2. **日志验收**：每套数据跑少量 case，确认 cost、答案、policy/trace 和失败记录可追溯；确认私有 intent 未泄漏。
3. **开发 pilot**：估计样本需求，冻结正式配置、方法支持范围、参数水平、案例选择规则和总运行预算。
4. **正式运行**：三个数据集执行同一矩阵；可断点续跑，失败不消失，不因结果不利修改配置。涉及新增收费服务或超出批准资源预算时先报告。
5. **交付**：完整数据目录、支持/失败报告、20 张图及其数据和脚本、真实 policy 案例、可重复生成结果的命令。

验收以数据完整性和协议执行为准，不以 XGAP 必须获胜为准。无法完成的外部比较或图明确列为缺失，不填模拟数值、不补造策略分支。
